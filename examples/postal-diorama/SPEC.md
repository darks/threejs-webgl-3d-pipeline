# Juniper Post & Telegraph — 场景制作规格

Run ID: `postal-example`  
Project root: `examples/postal-diorama`

## 需求与设计来源

原始需求（路径已归一化）：「制作一个欧美低多边形卡通风的邮电局」，并要求在项目工作区下新建专用产出目录。

以下地域、年代、尺寸、交互与预算均为 **Director 内部设计假设**，不是用户另行提出的要求。制作一个可以旋转观察的精致邮电局街角微缩模型；英文建筑名 **JUNIPER / POST & TELEGRAPH**，界面以简洁中文为主。采用约 1920 年代北美小镇公共建筑结合欧洲童话模型的温和语汇，不追求历史复原。项目是可运行 Three.js 场景，不能用概念图当成三维背景替代几何。

## 视觉核心

“清晨第一封信”：奶油色两层邮电局、深松绿折面屋顶、砖红色公共邮筒，在温暖晨光中形成安静而活泼的街角。主体是精心搭建的小型公共建筑，而不是孤立的方盒子。屋顶、门廊、台阶、檐口、窗框形成层级；可见电线、绝缘子和侧翼电报窗口让电报功能有三维证据。

构图按 **建筑 > 红邮筒/入口 > 电报侧翼/电线 > 街角配景** 组织。主建筑约占默认画面可见主体面积 60–70%；道具留出呼吸空间，不能用大量散件弥补建筑薄弱。底座完整入镜，外缘到画面至少保留 5% 边距，建筑顶端保留 7–12% 边距。

### 建筑与场景范围

- 使用 Y 向上，1 unit = 1 meter，前立面朝 +Z；平坦街角底座约 12 × 9 m，厚 0.5 m，边角切削或倒角，上表面平整。草地与铺装采用几何分区，避免起伏承载面带来不必要接触复杂度。
- 主楼约 6.4 m 宽、4.3 m 深，主体墙高约 4.6 m，坡屋顶最高约 6.4 m。两层比例，入口和门廊有明确厚度，门洞高约 2.0 m。整体略矮胖，不能细长成塔。
- 右侧接低一层电报营业侧翼，约 2.1 × 3.0 m，最高约 3.4 m；与主楼形成清楚的高低体块。侧翼外侧可见 `TELEGRAPH` 窗口或小牌和线缆引入点。
- 主屋顶是有厚度的四坡或双坡折面屋顶，选择一种锁定；正面中央小型钟面山墙/钟楼帽增加公共建筑身份，最高点不超过约 7.1 m。不能将其做成高耸教堂钟塔。屋顶有分段脊、浅色檐口与少量烟囱/通气件，装饰服从轮廓。
- 前立面宽招牌 `POST & TELEGRAPH`，上方小字 `JUNIPER` 可选。保留足够的招牌平面，字形清晰、不贴穿、不被柱子或树遮挡。招牌可用高分辨率 CanvasTexture；字体须等待就绪，使用本机系统字体回退而非依赖远程字体。
- 建筑必备：台阶两至三级、入口平台、双柱小门廊或厚门头、实心框玻璃门、立体窗框与窗台、二楼窗组、墙脚基座、侧面细节。后面保持合理的墙/窗/屋顶收口，不要求室内装饰。
- 邮政道具：前左区域一只显眼砖红邮筒，具有投信缝、厚顶盖、脚座及浅色信封标记；入口附近 3–5 个绑带包裹与一个小型邮件手推车（两轮、把手、托盘）。包裹不能遮住门或台阶。
- 通信道具：右后缘两根木制电报杆，以 1–2 根有轻微弧垂的粗细合适电线连接；横担、陶瓷绝缘子必须可辨。末端引线进入侧翼高处。杆子和线不横切主招牌、钟面或入口，不侵入相机主视线。
- 配景限一棵有明确分面树冠的树、3–5 丛小灌木、少量草簇、街角路缘/石铺路、一个长椅或路灯（择一）。树放主楼后左，不能盖住屋顶主体。铺装使用大块面和少数色差，不能做密集噪声。
- 不做可进入室内、完整街区、角色、汽车交通、天气系统、真实运营模拟、实时物理、音效或昼夜循环。没有无依据的真实品牌。

## 色彩、形体和材质规则

主色比例：奶油墙约 40%，松绿/青绿屋顶与门窗约 25%，沙色/浅暖灰地面约 20%，砖红邮筒与招牌点缀约 10%，深棕木件及黄铜约 5%。建议起点：墙 `#F2D9A3`，墙脚 `#C69D75`，屋顶 `#28645C` / `#3C7A6E`，红 `#C84D3D`，深色文字 `#244843`，石板 `#D9CBB1`，背景 `#DCE5D6`。后续可调但不能失去暖墙、冷顶、红邮筒的关系。

所有材质主要为 matte，roughness 通常 0.75–1.0，metalness 通常 0；黄铜细节可低度金属化。低多边形来自实际切面、简化轮廓和适度平面色差，不是随机三角噪声。树冠采用少量多面体团块，杆/轮/烟囱 6–12 边。重要墙角、台阶、框件有 0.03–0.10 m 的可见切角或分层边，不强制每个小件倒角。窗玻璃为深青色不透明/低透射面，使用简单暖色内部面和少数反光色块，不需物理透明折射。

禁止高光塑料感、照片纹理、大面积斑驳噪声、逼真金属镜面、粗黑全场描边、景深模糊、过曝白墙、过浓橙滤镜。不要做成西部片平板假立面或现代快递仓库。字体选粗衬线或温和的块状大写，文字是建筑的一部分，界面文字不替代建筑招牌。

## 相机与界面

默认 `overview`：正交或低透视感镜头，前右三分之四视角，可同时看到主招牌、门廊、右侧电报侧翼与两根杆子。参考位置方向 `(13, 10, 15)`，lookAt 约 `(0, 2.1, 0)`；具体距离/视锥由 Architect 按完整底座校准。采用 +Z 为正面。

`closeup`：前方略偏左或右，集中入口、红邮筒、招牌和包裹接触，必须有至少一处窗框/门廊厚度证据；不能简单裁到只剩墙。`lowangle`：前右较低位置，地面和台阶接触、檐底/屋顶厚度、侧翼连接清晰；不从底座下方看穿。`wireframe` 复用 overview，相机不变，退出后恢复原材质。

鼠标左键拖动轨道旋转，滚轮缩放，允许环绕 360°；俯仰角限制约 25°–78°（从 +Y 轴计），禁止到地下，限制缩放到近景仍不穿入屋体。可禁用平移或把 target 限制在主体周边小范围。触摸单指旋转、双指缩放。复位视图恢复默认 framing 和互动初始状态。

界面只保留左上小型标题/一句副标题、下方紧凑视角与操作工具条，合计占画面不超过 12%；不做侧栏、统计仪表盘或大卡片。界面风格与奶油/墨绿呼应，须有键盘 focus 和可读中文标签。大部分屏幕应是模型。`?clean=1` 隐藏全部 HTML UI 和调试辅助，保留建筑固有文字及场景内容。

## 有限互动与可执行用例

1. **投递一封信**：点击红邮筒或界面的“投递信件”按钮，出现一封小奶油信封从邮筒前方短距离移动并进入投信缝；邮筒盖/投口挡板可小幅转动，随后复位。总时长 1.0–1.8 s。运行中再点不叠加动画，结束后可重复。成功后短暂显示“信件已收妥”且不弹大面板。验收：点击一次看见移动和消失，再次点击仍能完成；动画完成后没有漂浮残留物。
2. **电报信号**：点击电报侧翼的小通信牌/窗口或“发送电报”按钮，侧翼信号灯按固定短长节奏闪 3–5 次，约 1.5 s，结束回到初始暖暗色。可以给侧翼窗口小幅暖色亮度反馈；不用沿电线飞行的霓虹粒子。并发点击去重，完成后可再次触发。验收：灯色/发光强度确实改变且复位，不影响材料线框恢复。
3. **观察与复位**：逐个切换 overview/closeup/lowangle，画面和相机状态有实际变化；切 wireframe 后可见全场线框，退出恢复；拖动与缩放可用；点击“复位”恢复 overview、邮件动画初态及电报灯初态。

无需门扇互动，入口门保持关闭。无需玩家碰撞或可行走导航；相机限制防止常见的穿地和极端缩放。地面/平台/屋顶等有意装配嵌入须在蓝图列 allowedOverlap；包裹、邮筒、车轮、柱脚、树干在 closeup/lowangle 中不得出现明显悬浮或穿进台阶。可见接触锚点误差目标 ≤ 0.03 m。阶梯步面水平，顶级与平台连续，门底对应平台。

## 灯光与视觉基准

默认温暖早晨、清爽空气。主方向光从画面左上/建筑前左照来，柔和短中长投影落向右后；环境填充使暗面仍有层次。使用柔和接触阴影确保底座/建筑/道具接地，避免厚黑阴影。背景纯浅鼠尾草/暖灰，无照片天空和地平线干扰；底座像高质量玩具模型悬于统一工作室背景，底部可用轻柔接地影。

概念图必须锁定：完整切角底座、前右三分之四相机、两层奶油主楼、绿坡顶、小钟山墙、右侧低电报侧翼、前左红邮筒、右后双电报杆、后左分面树。图像为美术参考，尺寸不是测量依据。若图像文字/线缆出错，按本规格及蓝图纠正。

阶段五比较 2–3 组相同相机的参数：A 清爽暖晨（默认方向），B 柔和中性日光，C 可选稍暖傍晚。选择依据是轮廓层次、浅墙不过曝、屋顶切面、邮筒显眼、电报侧翼可读，不能以更亮或更写实为胜。

## 目标设备、预算和证据

目标桌面 Windows 上当前可用 Chromium 系浏览器，鼠标与键盘；标准验收视口 1440 × 1000、DPR 1，手机兼容检查 390 × 844。截图统一标准桌面视口/DPR/随机种子/动画时刻。初次打开须无交互即可呈现完整默认构图。

几何/资源上限（必要检查）：实际渲染三角形 ≤ 100,000，draw calls ≤ 350（正常 overview，阴影相关计数需记录统计口径），场景自有纹理 ≤ 8 张，单张最长边 ≤ 2048，场景自有静态资源合计 ≤ 10 MiB（不含 npm 依赖、截图与概念图）。预期实际主体能以 20k–60k 三角形实现，不为了填预算增面。屋顶分段、窗框、铺装等重复件尽量共享几何/材质或实例化。默认 DPR 上限 1.5；截图强制 1。

性能目标（须实测才能声明）：目标设备普通 overview 稳态接近 60 FPS，连续 10 秒采样中位帧耗时 ≤ 20 ms、95 分位 ≤ 35 ms。实际记录浏览器/WebGL renderer、视口/DPR、采样时长、结果；虚拟化/软件渲染下记录真实结果与限制，不冒充桌面 GPU 性能。首次可交互目标 ≤ 5 s 本地服务，实际由 sceneReady 计时。不得为追求 FPS 删除身份关键几何。

必要工程检查：依赖安装/构建成功；无 pageerror、必要资源加载失败、WebGL context loss；所有互动用例与清洁捕获通过；四张图可解码、非空且视角真实变化；预算统计有实际数据。

## 必须实现的生产接口

遵循技能 execution-contract：`window.sceneReady` Promise；`window.setCameraMode(mode)` 支持四模式并等待真实渲染；`window.applyTuningParams(params)` 校验并应用；`?clean=1`；确定性动画冻结/跳转时间能力，捕获时信封未触发、信号灯为初态；`scripts/capture_views.mjs` 输出四图和包含源码/参数指纹的 manifest。不使用未经等待资源的固定 sleep 冒充就绪。

曝光、主光颜色/强度/方向、环境强度、背景色、阴影、材质颜色/粗糙度、相机 framing 集中参数化。可调范围由 Architect/Lead_Dev 在实现时提供；变化必须真实影响渲染。

独立几何评审最多 5 次、灯光候选 2–3 组且该阶段评审最多 3 次、材质改进最多 2 轮；每轮使用新 Critic，四维均分 ≥ 9.0、无未解决 blocker/major 且必要检查通过。所有输出均留在本 project root 中。界面、画廊和截图如实反映当前通过的版本，不编造验收。
